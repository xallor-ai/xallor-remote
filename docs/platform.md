# 租户、可信身份与会员权益

SSOT：资源归属、调用者、设备访问与权益的边界。操作系统执行见 [os.md](os.md)，传输字段见 [protocol.md](protocol.md)，现有数据库结构见 [relay.md](relay.md)。

产品以命令、文件为中心。GUI 是本机 Runtime 的 CLI 配置入口，展示本机 ID/授权码、连接列表、Agent 接入方法与远程终端。以下服务端模型不要求桌面增加审计、审批或租户管理台。

## 1. 当前实现与待完成范围

| 能力 | 状态 |
| --- | --- |
| 显示设备号码与内部 UID 分离 | 已实现；正常重连保留 UID，撤销后重建生成新 UID |
| 独立共享授权记录与连接绑定 | 已实现；连接绑定设备 UID + 授权 ID，授权码哈希恢复旧值不复活旧连接 |
| 身份/授权事务与路由隔离 | 已实现；数据库等待不持有全局路由锁 |
| 个人/组织租户、用户/服务主体、成员关系 | 已实现本机运维签发、续签、撤销、成员停用/恢复与调用身份验证；尚无用户注册、已有主体加入其他空间的管理入口 |
| 设备认领、跨租户共享、身份委托、授权撤销传播 | 待实现；现有共享码不代表调用者账号 |
| 权益覆盖值、真实资源周期租约、最小用量 | 待实现；固定 inflight 上限和 IP 保护不是会员额度 |
| 账号登录与支付集成 | 待实现；当前凭据由 Relay 运维签发，通过 Runtime 导入，不是浏览器登录 |

基础采用模块化单体。身份、授权、权益与准入有独立职责，可以先与 Relay 同进程部署；按实际负载拆部署。不能在 stdout 转发时访问登录或支付服务。

## 2. 长期对象关系

| 对象 | 职责与归属 |
| --- | --- |
| User | 登录身份，不直接替代资源的归属边界 |
| Tenant | personal / organization；拥有设备与资源预算。个人账号也有个人空间 |
| Principal | 用户或服务账号的可信调用主体；Agent 使用可撤销委托，不能自报身份 |
| Membership | 主体与租户的有效成员关系、角色及版本 |
| Device | 内部 UID、显示号码、归属租户、上线凭据版本；显示号码仅用于路由与配对 |
| AccessGrant | 独立 ID、目标设备、被授权主体或 bearer、允许操作、有效期、撤销/版本状态 |
| Subscription | 生成租户默认权益；支付客户与付款联系人另行关联 |
| Entitlement / Override | 功能值或额度值、租户/主体作用域、有效期、策略版本 |
| Session / Job | 真实执行或终端生命周期、可信调用上下文、资源租约 |
| Usage | 费用归属、实际调用者、指标、数量、时间与去重标识；不含命令、路径、文件或 stdout |

当前 `internal/access` 只承担设备实例和共享授权绑定。不能给未实现的成员关系或账本写占位值，并宣称租户基础完成。存储迁移保留显示号码与凭据，但运行时只使用最终模型，不保留旧字段别名或双写。

`internal/principal` 定义签发方推导的调用身份；Relay 的 SQL 存储实现认证、凭据及成员版本校验。当前新调用同时校验账号凭据（若配置）和目标共享授权码，inflight 保留可信调用主体。此阶段没有设备所属租户、主体级设备 ACL 或费用归属；不能据此宣称租户资源已经隔离。

## 3. 可信身份与设备访问

同一共享授权码可以被多人持有，因此不能用 grant hash、IP、设备号或 agent_name 当作某个会员用户。匿名共享模式继续支持无账号和自托管，但不伪造一个付费主体。

可信请求上下文由认证与授权模块推导：authority、调用主体、主体所属租户、目标设备 UID、设备所属租户、费用归属租户、授权 ID/版本、策略版本与会话身份。不能信任客户端 JSON 自报 tenant_id 或 principal_id。authority 是身份签发与资源命名空间，多个自托管 Relay 上的相同显示号码不得串成同一资源。

设备认领必须证明设备所有权或持有设备级凭据；知道显示号码或共享授权码不等于拥有设备。跨租户转移必须使旧授权上下文失效并处理既有会话，不能只修改 owner_tenant_id。移除成员、撤销委托和授权也必须传播到缓存及后续准入。

无账号共享授权和账号认证是两种明确身份路径，不是旧客户端兼容分支。每种路径都产生自己的可信授权上下文。当前共享绑定只阻止失效连接继续发起新请求，不承诺停止所有已经启动的后台作业；完整作业撤销语义需要执行生命周期与授权版本一起落地。

本机多账号采用隔离 profile，或在连接池、正在建立连接的合并键、回执查询与幂等键中包含完整可信作用域。只按目标显示 ID 复用连接不能证明跨账号隔离。MCP/CLI/GUI 始终经本机 Runtime，不各自实现远程认证栈。

当前 Runtime 连接与建连合并键包含 Relay、目标、共享授权摘要、账号凭据摘要和本机切换代次。重新导入或清除账号会关闭旧控制连接；即使 A→B→A，未完成的旧建连也不能写回连接池。凭据固定到导入时的 Relay 地址，地址变化需明确清除或重新导入；诊断同样使用当前凭据。handoff、回执查询与幂等缓存的完整主体作用域仍待实现。

账号撤销或成员停用阻止该身份路径后续通过验证的新请求；恢复成员后需要新握手。正在执行的作业不会因这一操作自动终止，原连接仍可取消自己的作业。显式清除账号后仍可使用持有的共享授权码：当前共享码没有租户 ACL，因此成员停用不等于撤销全部设备访问权。

## 4. 权限与权益分离

设备访问授权决定能操作哪些资源；会员权益决定允许使用的功能和资源预算。付费不能赋予未经授权的设备访问权，组织成员也不自动获得所有设备权限。

权益以稳定功能键及数值表达，套餐是生成默认权益的配置，不在各入口判断 isVIP。例如 exec.concurrent、terminal.concurrent、relay.bytes_per_second、relay.monthly_egress_bytes、file.max_transfer_bytes。协议帧与内存硬上限独立存在，不能随套餐无限放大。

“给某个人提额”使用带作用域、有效期和版本的 Override。例：团队总并发 20、普通成员 2、某成员临时 8；目标 Runtime 上限 4 时，该成员在此设备仍最多 4，且受团队剩余预算约束。覆盖值不直接授予操作权限。

跨租户共享必须明确费用归属：调用者租户承担自己发起的资源用量，或设备所有者显式提供赞助额度。不能根据转发 IP 猜账单归属。订阅取消影响权益，不删除设备身份或用户文件。

## 5. 准入、资源生命周期与用量

1. 认证调用者，并验证设备访问权限。
2. 解析有版本与有效期的权益快照。
3. 原子预留租户、主体、设备需要的资源，产生有期限的租约。
4. Relay 路由，目标 Runtime 再检查本机策略与容量。
5. 实际作业结束后释放资源，执行中续租；重复取消、重复终态不得重复返还。
6. 最小用量记录以独立标识去重；不从命令审计或请求次数推断计费。

handoff 的提交请求结束不代表后台 worker 结束；终端断线保留仍占资源；恢复连接不重放命令。租约到期也不能直接把仍在执行的作业当成已停止：需要目标侧停止/隔离或确认结束，网络分区时保留不确定状态。不得自动重放未知结果的有副作用操作。

IP 频率/流量保护独立于商业额度；同一 NAT 下的人不共享会员身份。多 Relay 实例需要设备连接归属与路由，单纯共用数据库无法保证在线状态或资源账本一致。

## 6. 开发顺序与验证门槛

先完成可信主体、租户关系、设备归属、分享和缓存作用域，再做权益与原子租约，最后接具体套餐和支付。每一步必须有实际调用链，不以未使用的接口和空表冒充实现。

验证至少覆盖：跨租户资源不可访问、伪造上下文失败、认领/转移证明、成员与授权撤销、连接和回执隔离、并发预留竞争、到期和断网、实际后台任务结束、重复释放/计量，以及既有无账号共享与正常重连。验证范围与状态以每个 PR 的最终提交证据为准。
