# 崩溃后来源隔离区回收：待确认的权限边界

状态：设计提案，尚未授权或实现历史文件删除。沿用已确认的 Runtime 接管、
不重放不确定副作用、无原始证明则拒绝的原则。本文不改变已完成的正常资源收尾。

## 已核实事实

当前隔离副本的创建回执仅在进程内保存；资源表有 operation/namespace/attempt
和内容摘要，没有跨崩溃的删除权限。不能扫描 `xr-provenance-*` 后推测归属。

2026-11-17 原生探测使用原始打开句柄：Windows NTFS 的完整 128 位 file ID
区分了同内容替换，但替换对象的创建时间与原对象完全相同；Linux 测试 tmpfs
的 statx 返回 mask=0x17ff，没有请求的 BTime，多个不同对象还共享 ctime/mtime。
两端 16 项身份关系检查通过，已知探测文件非递归清理、容器清理均无错误。
这只是当前文件系统上的事实，不是崩溃删除权限证明。

证据：外部 `non-gui-release/quarantine-identity-native/{report,analysis}.json`
及 findings.md，记录源码/二进制哈希与实际字段。官方限制：
[Microsoft 文件 ID 可被复用](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information)，
[Linux statx 需检查实际返回的字段 mask](https://man7.org/linux/man-pages/man2/statx.2.html)。
创建时间、ctime/mtime、哈希或文件名均不单独授予回收权限。

## 可选边界

| 方案 | 能完成的工作 | 限制 |
| --- | --- | --- |
| 保留原生对象引用的持有者负责清理 | 可另行研究对象引用与对应删除语义 | 当前只保持根句柄，成员是内存元数据；不能声称现有回执或新增守护角色已经提供物理连续性保证 |
| Runtime 专属、永不复用的来源槽位 + 持久分配/封存回执 | 在明确授权的私有资源区内，执行原操作的显式核对与受限回收 | 这是比当前全局临时目录更明确的管理权限；仍需 worker 终止、资源组、命名空间与回执完整性证据 |
| 缺少活回执时始终保留 | 不增加历史删除权限 | 历史债务只能保留并交付人工处理，不能宣称自动恢复完成 |

不采用“把 file ID 加时间戳存进 JSON 就自动删除”的方案。原生探测与官方契约
都不支持这种推断。

## 建议：第二项，但仅给来源隔离副本划定权限

1. 新的已准入操作把来源副本放入 Runtime profile 下独立的私有隔离区，按原
   operation/resource ID 派生固定槽位。相同槽位永不重新分配；重复操作只查询。
   profile 重建或记录回滚也不能重新认领旧槽位。
   standalone verify 和未认证输入不能因此创建 profile 或取得这项权限。
2. 权限来源是用户明确划给 Runtime 管理的这一资源区，加上原始分配记录；
   原生对象身份、原始内容摘要、封存成员集用于拒绝已检测到的漂移，不能反过来创造权限。
   原始 bundle、当前/历史运行 activation、工作目录与用户文件均不在该授权内。
   第二项授权的是专属命名空间内的有界逻辑资源管理，不保证重启后仍是创建时的
   物理对象；ID、时间戳及摘要组合一致也不能排除删除再创建的 ABA 情况。
3. 分配意图先于创建；随后记录实际根/成员对象证据及有界封存回执。所有状态
   写入关联原 namespace、operation、attempt/generation，并使用 revision CAS。
   Windows 不截断 128 位 file ID；Linux 缺失字段明确记录，不用 ctime 补出生时间。
   所选核对策略依赖的字段、所有权或 worker/后代终止证明缺失、不支持或不可
   验证时，只观察并保留 unresolved；批准该管理边界也不豁免这些要求。
4. 回收只在用户显式核对原操作时进行，不自动后台清扫。必须确认原 worker 不会
   再继续分配/使用槽位、相关 verifier/probe 家族已结束，且独占生命周期准入。
   当前只持有锁、进程号不存在或收到 ready 都不单独满足这些条件。
5. 检查整个已记录成员集后，才逐个非递归移除已授权成员，最后移除空目录。
   未知成员、链接/根替换、记录缺失、实例/卷/命名空间连续性不明、无法封存的
   分配间隙均保持 unresolved。不得删除再试、递归扫目录或从旧目录名称迁移权限。
6. 原操作、原 outcome/effects 保留；新观察与回收结果追加记录。回收源文件不等于
   原安装成功，也不恢复历史 ready ACK，更不允许重放 install/stop/start。

这一方案不是“永久唯一对象 ID”。它要求一个明确受 Runtime 管理的私有区，并
保留当前模型不防御同用户恶意篡改日志/内存、以及非协作文件系统竞态的边界。
如果需要连同这些情况也保证物理对象连续性，须另行论证原生对象引用及对应
删除语义；现有回执或新增守护进程本身均不提供这个保证。本提案不暗示能解决
pathname 比较与删除之间的竞态。

## 实施前后应保留的验收

- 分配前、创建后未登记、登记后未封存、封存后、删除后未记账等真实中断点。
  删除后未记账只能追加当前缺失观察，不能补造成功删除事实、settled 或历史
  ACK；缺少其它必要证据仍为 unresolved。
- 同内容替换、根替换、硬链接、未知成员、inode/file ID 重用、缺失 BTime、
  卷/挂载/主机变化，以及陈旧 revision，均不能因内容相同而扩大删除对象集。
- 原 worker 或 verifier/probe 仍可能存活时，核对只观察、不删除。
- 缺失证明与旧的全局临时目录保留；无自动 schema 迁移或追认创建回执。
- 正常运行与跨进程恢复分别做 Windows/Linux 原生测试；受控 verifier 不替代
  正式签名生命周期验收。

的历史保留行为。确认前只继续既有正常路径的修复和验证，不启用历史删除。
